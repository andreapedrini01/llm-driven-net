# Action Output Interface Documentation

## Overview

The Action Output Interface is a critical component of the LLM Integration Module that handles the structured output of validated network actions for future integration with the Northbound module. It provides a standardized format, comprehensive logging, and traceability for all network actions generated by the system.

## Purpose

The interface serves as the bridge between the LLM Module's action generation/validation and the future Northbound module that will execute these actions on the network. It ensures:

- **Structured Output**: Actions are formatted in a standardized, machine-readable format
- **Traceability**: Complete audit trail from intent to action execution
- **Future Integration**: Well-defined contract for Northbound module integration
- **Reliability**: Robust error handling and status tracking

## Key Features

### 1. Structured Action Packages

Actions are packaged in a comprehensive format that includes:
- Action details with execution parameters
- Validation and safety assessment results
- Execution order and dependencies
- Rollback plans for safe recovery
- Complete traceability information

### 2. Multiple Output Formats

Currently supports:
- **JSON**: Primary format for file-based integration
- **YAML**: Planned for future releases
- **Northbound V1**: Standardized format for Northbound module

### 3. Comprehensive Logging

All action outputs are logged with:
- Timestamp and unique identifiers
- Validation and safety status
- File paths and metadata
- Status updates throughout lifecycle

### 4. Status Tracking

Actions can be tracked through their lifecycle:
- `PENDING`: Action is being prepared
- `READY`: Action package is ready for execution
- `SENT`: Package has been sent to Northbound module
- `ACKNOWLEDGED`: Northbound module confirmed receipt
- `FAILED`: Action execution failed

## Usage

### Basic Usage

```python
from src.services.action_output import ActionOutputInterface
from src.models.actions import ActionSequence, ValidationResult, SafetyReport

# Initialize the interface
output_interface = ActionOutputInterface(
    output_directory="./output/actions",
    log_directory="./output/logs",
    enable_file_output=True
)

# Output validated actions
result = output_interface.output_actions(
    sequence=action_sequence,
    validation_result=validation_result,
    safety_report=safety_report,
    user_id="admin_user",
    save_to_file=True
)

# Access the results
package = result["package"]
file_path = result["file_path"]
record = result["record"]
trace_id = result["trace_id"]
```

### Creating a Northbound Package

```python
# Create a structured package
package = output_interface.create_northbound_package(
    sequence=action_sequence,
    validation_result=validation_result,
    safety_report=safety_report,
    user_id="admin_user",
    trace_id="custom_trace_id"  # Optional
)

print(f"Package ID: {package.package_id}")
print(f"Validation passed: {package.validation_passed}")
print(f"Safety approved: {package.safety_approved}")
print(f"Risk level: {package.risk_level}")
```

### Serializing to JSON

```python
# Serialize package to JSON
json_output = output_interface.serialize_to_json(
    package=package,
    pretty=True  # Pretty print for readability
)

# Save to file
file_path = output_interface.save_to_file(
    package=package,
    filename="custom_name.json",  # Optional
    output_format=OutputFormat.JSON
)
```

### Logging and Traceability

```python
# Log action output
record = output_interface.log_action_output(
    package=package,
    validation_result=validation_result,
    safety_report=safety_report,
    output_path=file_path,
    status=ActionStatus.READY
)

# Retrieve records
record = output_interface.get_output_record(record_id)
intent_records = output_interface.get_records_by_intent(intent_id)
sequence_records = output_interface.get_records_by_sequence(sequence_id)

# Update status
output_interface.update_record_status(
    record_id=record_id,
    status=ActionStatus.SENT
)
```

## Interface Contract for Northbound Integration

The interface provides a well-defined contract for future Northbound module integration:

### Integration Points

1. **File Location**: `./output/actions/`
2. **File Format**: JSON
3. **File Naming**: `action_package_{sequence_id}_{timestamp}.json`
4. **Log Location**: `./output/logs/action_output.log`

### Expected Workflow

1. LLM Module creates and validates action sequence
2. LLM Module calls `output_actions()` to generate package
3. Package is saved to file in output directory
4. Northbound Module reads package from file
5. Northbound Module executes actions in specified order
6. Northbound Module updates status via `update_record_status()`
7. Results are logged for traceability

### Getting the Contract

```python
contract = output_interface.get_interface_contract()

print(f"Contract version: {contract['contract_version']}")
print(f"Package format: {contract['package_format']}")
print(f"Action format: {contract['action_format']}")
print(f"Integration points: {contract['integration_points']}")
print(f"Expected workflow: {contract['expected_workflow']}")
```

## Configuration

### Initialization Parameters

- `output_directory`: Directory for action output files (default: `"./output/actions"`)
- `log_directory`: Directory for action logs (default: `"./output/logs"`)
- `enable_file_output`: Whether to write files (default: `True`, set to `False` for testing)

### Environment Variables

The interface respects the following environment variables:
- `ACTION_OUTPUT_DIR`: Override default output directory
- `ACTION_LOG_DIR`: Override default log directory

## Best Practices

### 1. Always Validate Before Output

```python
# Validate actions before outputting
validation_result = validator.validate_actions(sequence)
safety_report = validator.check_safety(sequence, network_state)

if validation_result.is_valid and safety_report.is_safe:
    result = output_interface.output_actions(...)
```

### 2. Use Trace IDs for Correlation

```python
# Generate or use consistent trace IDs
trace_id = f"trace_{intent_id}_{timestamp}"

package = output_interface.create_northbound_package(
    ...,
    trace_id=trace_id
)
```

### 3. Update Status Throughout Lifecycle

```python
# Track action lifecycle
output_interface.update_record_status(record_id, ActionStatus.SENT)
# ... execute actions ...
output_interface.update_record_status(record_id, ActionStatus.ACKNOWLEDGED)
```

### 4. Handle Errors Gracefully

```python
try:
    result = output_interface.output_actions(...)
except Exception as e:
    logger.error(f"Failed to output actions: {e}")
    # Implement fallback or retry logic
```
